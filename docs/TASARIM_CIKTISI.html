TASKFLOW

Görev ve Proje Yönetim Sistemi REST API — Bitirme Projesi Tasarım Çıktısı (Aşama 01)
Node.js Express.js RESTful Architecture MVC / Modüler Tasarım

1. Proje Tanıtımı ve İhtiyaç Analizi

Proje Amacı: Bir yazılım şirketinde ekip içi görevlerin oluşturulması, ilgili çalışanlara atanması, öncelik sıralaması (high, medium, low) ve tamamlanma durumlarının (pending, in-progress, completed) merkezi bir RESTful API üzerinden yönetilmesini ve anlık istatistiksel raporlama sunulmasını sağlamaktır.

2. API Mimarisi ve Klasör Yapısı (Architecture Design)

Proje, sorumlulukların ayrılığı prensibine uygun olarak katmanlı mimaride kurgulanmıştır:

taskflow-api/ ├── data/ --> JSON veri tabanı (Kalıcı dosya depolama) ├── docs/ --> Sistem tasarımı, test senaryoları ve Postman koleksiyonu ├── logs/ --> İstek logları (Logger Middleware - access.log) ├── src/ │ ├── controllers/ --> HTTP isteklerini yöneten denetleyiciler (Task, Report) │ ├── middlewares/ --> Ara katmanlar (Logger, Validation, Error Handler) │ ├── models/ --> Veri modelleri, filtreleme ve istatistik hesaplama mantığı │ ├── routes/ --> API rotaları (/api/tasks, /api/reports) │ ├── utils/ --> Asenkron dosya okuma/yazma yardımcıları │ ├── app.js --> Express uygulama yapılandırması │ └── server.js --> Sunucu dinleme noktası (Port 3000) ├── README.md --> Kurulum ve çalıştırma kılavuzu └── test-runner.js --> 16/16 Otomatik test paketi

3. Veri Modeli Tasarımı (Data Model & Schema)

Sistemde yönetilen Görev Varlığı (Task Entity) veri şeması:

Alan Adı Veri Tipi Zorunlu mu? Varsayılan Açıklama / Kısıtlar
id String Sistem Otomatik Benzersiz kimlik (örn: task-1792273746073-905)
title String Evet - Görev başlığı (En az 3 karakter)
description String Evet - Görev açıklaması (En az 5 karakter)
priority String Evet - Öncelik düzeyi: low, medium, high
assignee String Evet - Atanan çalışan kullanıcı adı (örn: ahmet, musa)
status String Hayır pending Durum: pending, in-progress, completed
createdAt String (ISO) Sistem ISO 8601 Oluşturulma zaman damgası
updatedAt String (ISO) Sistem ISO 8601 Son güncelleme zaman damgası

4. API Tasarım Dokümanı ve Endpoint Listesi

A. Temel CRUD Endpointleri (Zorunlu Kapsam - 100 Puan)

İşlem Metot & URL Açıklama / Gövde Durum Kodu
Görev Ekleme POST /api/tasks Yeni görev oluşturur. Body: title, description, priority, assignee 201 Created
Görev Listeleme GET /api/tasks Sistemdeki tüm görevleri dizi olarak döner. 200 OK
Görev Detayı GET /api/tasks/:id Belirtilen ID'ye sahip tekil görevi getirir. 200 OK / 404
Görev Güncelleme PUT /api/tasks/:id Görev bilgilerini veya durumunu günceller. 200 OK
Görev Silme DELETE /api/tasks/:id Görevi sistemden kalıcı olarak kaldırır. 200 OK

B. İleri Seviye Filtreleme, Arama ve Sayfalama (İsteğe Bağlı 01)

  • Duruma Göre Filtreleme: GET /api/tasks?status=completed
  • Önceliğe Göre Filtreleme: GET /api/tasks?priority=high
  • Anahtar Kelime Arama: GET /api/tasks/search?keyword=backend
  • Çalışan Bazlı Listeleme: GET /api/tasks/assignee/musa
  • Sayfalama ve Sıralama: GET /api/tasks?page=1&limit=10&sort=createdAt&order=desc

C. İstatistik ve Raporlama Servisleri (İsteğe Bağlı 03)

  • Tamamlanan Görev Raporu: GET /api/reports/completed
  • Bekleyen Görev Raporu: GET /api/reports/pending
  • Genel Sistem Özeti: GET /api/reports/summary (Toplam, tamamlanma yüzdesi, öncelik dağılımı)
